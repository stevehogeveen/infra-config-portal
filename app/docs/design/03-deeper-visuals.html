Deploying a VM is two questions, never one

Where does it run, and where does it live? The panel asks them separately because the answers are independent — and that is exactly the thing a rack diagram can never show.

Visual 4

vCenter, the chicken-and-egg VM

vSAN needs vCenter to manage it, and vCenter is a VM that needs somewhere to live. The panel shows the order that resolves the loop.

What I’d build first

Visual 2 — the drive allocation panel. It is the smallest piece that delivers the boot-pair idea, it maps onto endpoints that already exist (hpe-raid-intent, hpe-raid-plan-preview, hpe-storage-discovery), and every later screen depends on knowing which drives are spoken for.

Then Visual 1’s stage behaviour in the main workspace, since it is mostly conditional rendering of the layout you already approved — no new data required.

Visuals 3 and 4 come after ESXi actually installs, because until a host runs a hypervisor there is nothing to place a VM on.
